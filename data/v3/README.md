# Neural Search Dataset V3

## Purpose
V3 replaces the V2 generic document template with topic-specific technical explanations and more discriminative query variants. It is designed for the existing from-scratch neural semantic-search experiment, not as a claim that the model will automatically reach a target score.

## Files
- `documents.json`: 100 technical documents with stable IDs, categories, titles, detailed bodies, keywords, and aliases.
- `train.json`: 800 query-to-document positive pairs (8 per document).
- `validation.json`: 200 pairs (2 per document), phrased differently from training.
- `test.json`: 200 pairs (2 per document), held out for final evaluation.
- `validate_dataset.py`: schema, referential-integrity, count, duplicate-query, and split-leakage checks.

## Important evaluation note
This dataset is synthetic and the query/document relevance labels are generated by construction. It is suitable for experiments and learning, but not a substitute for human-labeled production queries. Do not tune repeatedly against the test set. Use validation for decisions and run test once after selecting the final checkpoint.

## Compatibility
The JSON envelopes match the project's V2 style:
- documents: `{"documents": [...]}`
- pair files: `{"pairs": [{"query": ..., "document_id": ...}]}`

Documents retain the existing IDs so code that uses `document_id` continues to work. Document records add `keywords` and `aliases`; existing code can ignore these fields. The intended text fed to the encoder is `title + text`; do not feed `keywords`/`aliases` unless you explicitly run a separate controlled experiment.

## Recommended training setup
1. Build vocabulary from document title + body and training queries only.
2. Use the exact same document text builder in training, validation, checkpoint evaluation, and inference.
3. Train with multi-positive contrastive loss and in-batch negatives, ensuring duplicated positive documents are not treated as negatives.
4. Select checkpoints by validation MRR (or a predeclared metric) and save the vocabulary/configuration with the weights.
5. Keep V2 unchanged for reproducibility; point a new experiment to `data/v3/`.

- Documents: 100 (10 topics × 10 documents)
